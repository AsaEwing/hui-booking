# hui-booking

展牆位置預訂系統，供學生填寫志願序，依「時間排序制」或「抽籤制」自動分配展牆位置。

built on Cloudflare Pages + Workers Functions + D1 (SQLite)

---

## 頁面

| 路徑 | 說明 |
|------|------|
| `/` | 學生登入 / 註冊 |
| `/book.html` | 填寫志願序（登入後） |
| `/result.html` | 排位結果（公開頁面，不需登入即可查看；未登入時姓名會部分遮蔽） |
| `/verify-lottery.html` | 抽籤結果驗證工具（公開頁面，不需登入，完全離線可用） |
| `/example.html` | 抽籤範例說明（公開頁面，不需登入，用固定範例與真實專案資料示範抽籤機制） |
| `/admin.html` | 管理員 / 超級管理員面板 |

## 角色說明

| 角色 | 登入方式 | 權限 |
|------|----------|------|
| 學生 | 自行註冊，密碼自訂（也可選擇不設密碼，見下方說明） | 填寫志願、查看結果、撤回志願 |
| 一般管理員 | 帳號由超級管理員建立 | 管理學生、專案、複製專案、查看排位、執行抽籤 |
| 超級管理員 | 同上，或 `SUPER_PASSWORD` 環境變數登入 | 含以上所有權限 + 一鍵重置學生、設定人數上限 |

### 免密碼帳號（選填，風險自負）

學生註冊時可選擇不設密碼，需輸入確認語句（「我了解風險」）才能啟用。啟用後任何人只要知道姓名就能登入該帳號，系統會在管理員畫面上標示此帳號為「免密碼」。管理員重置該學生密碼時會自動清除此標記，恢復一般密碼保護。

### 超級管理員緊急登入（忘記密碼）

若超級管理員帳號密碼遺失，可在 Cloudflare Dashboard 設定環境變數 `SUPER_PASSWORD`，以任意帳號名稱搭配此密碼從 `/admin.html` 登入，取得超級管理員權限。

### 記住上次登入的姓名

學生登入頁會把上次登入成功的姓名記在瀏覽器（`localStorage`），下次進入登入頁時自動帶入姓名欄位，減少重複輸入。**只記姓名，不記密碼**，密碼每次仍須手動輸入。

## 分配方式

每個專案建立時二選一，一旦有人提交志願後就會鎖定，無法再變更。

### 1. 時間排序制（預設）

1. 先比對所有人的**第 1 志願**，若該位置只有一人填寫，直接取得；多人填同一位置，由**提交時間較早者**優先取得。
2. 取得第 1 志願者不再參與後續競爭；剩餘的人進入**第 2 志願**的競爭，規則相同。
3. 以此類推，直到所有人都分配到位置，或所有志願序用盡為止。

### 2. 抽籤制

- 填寫志願時系統不看提交時間，所有人一律平等參與抽籤。
- 志願填寫截止後，由管理員在後台執行一次「執行抽籤」（建議全程錄影存證）。系統會產生一個隨機種子，一次性決定所有人的優先順序，之後每一輪比序都沿用同一份順序 —— 這是**隨機序列分發（Random Serial Dictatorship）**機制，跟許多學校免試入學的抽籤分發採用同一套公平原理。之後的分配邏輯與時間排序制相同，只是把「提交時間」換成「這份隨機順序」。
- 抽籤**只能執行一次**，執行後會鎖定：無法再變更分配方式，學生也無法再修改或撤回志願。
- 抽籤前，`result.html`（公開頁面）與 `admin.html`（管理後台）顯示的都是「登記狀況」（每個位置目前有幾人登記，平面圖用顏色深淺呈現，不顯示最終結果）；抽籤完成後才顯示正式結果，兩邊的圖例文字也會跟著切換。
- 每次抽籤都會存一筆**不可修改**的稽核紀錄（`lottery_draws`：種子、執行時間、執行者身份、當時完整的報名/結果快照），管理員可在後台隨時「查看抽籤紀錄」，下載人類可讀的文字紀錄或機器可讀的 JSON。

### 組合位置（可選）

專案可設定 `max_combo_size`（預設 1，維持單選）。大於 1 時，學生可以在單一志願序裡勾選多個位置組成一組（例如需要相鄰兩面牆），系統會把整組視為一個單位判斷是否可分配（必須所有位置同時空著才會整組給）。不同志願序之間允許部分重疊（保留作為備援策略的空間），但**禁止兩個志願序選出完全相同的一組位置**（沒有意義，只會浪費一個志願序名額）。

### 結果自動關閉（可選）

專案可設定 `active_until`，超過此時間後 `result.html` 會自動視為關閉（不需要額外排程機制，讀取當下即時比對時間點判斷）。設定值必須晚於截止時間（`close_at`）至少 3 天。`result.html` 會依目前時間動態顯示開放/截止狀態（尚未開放／開放中／已截止），有設定自動關閉時間的話也會一併提醒。

## 公開驗證機制（抽籤制專屬）

抽籤制的公正性需要讓所有人 —— 尤其是不熟悉技術的人 —— 都能自行驗證，系統為此設計了四層機制：

1. **`/result.html` 完全公開**：不需登入即可查看排位結果（`/api/result` 本來就沒有身份驗證機制，這裡只是讓前端行為跟後端一致，避免「假的登入門檻」造成錯誤的安全感）。未登入時姓名會部分遮蔽保護隱私（例如「陳偉」→「陳Ｘ」、「歐陽小明」→「歐ＸＸ明」、「Peter Yu」→「Peter X」），登入後（不論學生或管理員）可看到完整姓名。
2. **一鍵下載驗證資料**：`result.html`（任何人）與 `admin.html`（管理員）都能下載這次抽籤的完整 JSON（專案名稱、種子、報名快照、結果快照），兩邊格式一致。
3. **`/verify-lottery.html` 離線驗證工具**：不需登入、不連任何伺服器（連 Google Fonts 都不連），把抽籤演算法完整複製進頁面本機執行。上傳或貼上下載的 JSON 後，會在瀏覽器本機重新計算一次抽籤結果，跟檔案裡宣稱的結果逐筆比對，抓出任何被竄改的資料。頁面上附有「飛航模式自我測試」教學，讓使用者能親自確認整個過程真的沒有連網，也可以把頁面另存到本機長期保存。
4. **驗證雜湊值**：執行抽籤當下、查看抽籤紀錄、`result.html`、`verify-lottery.html` 都會顯示同一份資料算出的 SHA-256 雜湊值。建議在執行抽籤時連同畫面一起錄影/截圖存證；之後任何人都能重新計算比對，雜湊值不同即代表資料已被更動過。
5. **伺服器數位簽章**：執行抽籤時，伺服器會用只存在環境變數（`LOTTERY_SIGNING_KEY`，ECDSA P-256 私鑰）、從不外流的私鑰對這份資料簽章，存進 `lottery_draws.signature`。對應的公鑰以明碼寫死在 `verify-lottery.html` 裡，任何人都能離線驗證這個簽章是否有效。跟第 3 點的「重算結果自洽」不同，簽章能證明**這份資料真的是伺服器當時簽出來的**，而不只是有人事後拼湊出一份「數學上算得通」的假資料整組替換掉——這是目前最強的防偽層。此功能上線前執行過的抽籤紀錄沒有簽章，驗證頁面會顯示「無簽章可驗證」而不是判定失敗。

> 離線重算比對（第 3 點）只能證明「這份資料在數學上自洽」，並不能單獨證明「這份資料真的是當初的報名資料」——真正防止整組資料被偽造置換的是第 5 點的數位簽章；第 4 點的雜湊值 + 錄影/截圖存證則是給沒有簽章的舊資料，或想額外用肉眼比對的人一個備援方式。

## 抽籤範例與機率預估工具

`/example.html` 是給不熟悉抽籤機制的人（尤其是非技術背景的學生）用的說明頁面，公開、不需登入，分成三個分頁（可用網址 hash 直接連到指定分頁，例如 `example.html#own`）：

1. **範例**：幾組固定的手寫範例，逐輪列出抽籤過程中每個人在每一輪的成功/失敗與原因，適合完全不懂演算法的人照著讀。
2. **範例抽籤**：同一批範例資料，多加一顆「重新抽籤」按鈕，每按一次用不同的隨機順序重算最終結果（只重算結果表，不重新生成逐輪說明文字）。
3. **自己抽**：讓使用者選擇一個目前**尚未抽籤**的抽籤制專案，帶入該專案實際登記的志願資料模擬抽籤——姓名一律匿名化為「學生1」「學生2」等代稱，畫面最上方有醒目紅字警語提醒這只是練習模擬、非正式結果。這個分頁同時會算出每個人抽中第幾志願（或落空）的機率，姓名旁若有落空風險會加註 ⚠ 符號。

**機率計算：精確值 + 估計值兩種**。把大家的志願依「有沒有跟別人搶位置」分組，完全不相關的人各自獨立；有互相搶位置（含組合志願重疊、跨志願序的間接關聯）的人歸在同一個小群組：
- **11 人以下**：窮舉群組內所有可能的抽籤順序，算出**精確機率**。
- **超過 11 人**：改用**蒙地卡羅統計抽樣**（隨機模擬大量次數、用出現頻率估算機率，不是窮舉全部排列），畫面上以「約 X.X%」標示為**估計值**，滑鼠移上去可看模擬次數與誤差範圍。分三階段在背景執行緒漸進式更新：1萬次（約0.5秒，粗略）→ 10萬次（約5秒，誤差約 ±0.3%）→ 100萬次（約 45秒，誤差約 ±0.1%），每個階段跑完就更新畫面，不用整個等完才看到結果。

這套機率計算全程在 Web Worker（`public/lottery-prob-worker.js`）背景執行，不會卡住畫面。核心邏輯抽成共用檔案 `public/lottery-prob.js`，`example.html` 與 `admin.html`（後台「可能落空」預估，見下方「學生管理」）共用同一套，避免邏輯重複維護。這套計算是**展示 / 預估用**，概念上與正式抽籤的 `computeAllocation`（`functions/_lib.js`）一致，但屬於獨立實作——不是正式抽籤依據，正式結果一律以後台抽籤紀錄與 `verify-lottery.html` 的驗證為準。

## 附加位置工具（append-only）

管理員可在既有專案上使用「新增位置」工具，**只能新增新的展牆座標，無法修改或刪除既有位置**，避免誤觸導致已提交的志願或已分配結果失真。

## 管理員功能

### 專案管理
- 新增 / 編輯展覽專案
- 上傳平面圖，點擊標記展牆座標
- 附加位置工具（只能新增，不能修改/刪除既有標記）
- 設定開放時間（`open_at`）與截止時間（`close_at`），以及選填的結果自動關閉時間（`active_until`）
- 勾選「開放」控制學生是否能看到專案
- 選擇分配方式（時間排序制／抽籤制），抽籤制須填寫規則說明文字（供學生填寫志願前閱讀）
- 設定組合位置上限（`max_combo_size`）
- 複製專案（保留平面圖與設定，重置時間與開放狀態）
- 附加 Google Drive 資料夾連結（供學生上傳宣傳資料）
- 執行抽籤（僅限抽籤制專案，執行後鎖定，無法復原）、查看/下載抽籤紀錄

### 開放條件邏輯

| `is_open` | 時間狀態 | 學生可查看 | 學生可送出志願 |
|-----------|----------|-----------|--------------|
| ✅ 開放 | 未到開放時間 | ✅ | ❌ |
| ✅ 開放 | 在時間窗內 | ✅ | ✅ |
| ✅ 開放 | 超過截止時間 | ✅ | ❌ |
| ❌ 未開放 | 任何時間 | ❌ | ❌ |

### 學生管理
- 查看所有學生志願與分配結果（依專案篩選）
- 搜尋學生姓名
- 重置個別學生志願或密碼（重置密碼會一併清除該學生的免密碼標記）
- 匯出 CSV（含備註欄位）
- 抽籤前（抽籤制、尚未抽籤時）顯示「可能落空」預估：統計卡顯示風險人數，學生姓名旁加註 ⚠ 徽章，滑鼠移上去看機率細節（人數多時是蒙地卡羅估計值，詳見上方「抽籤範例與機率預估工具」），方便主動提醒（僅供參考，非正式抽籤依據）

### 超級管理員專屬
- 設定全系統學生人數上限
- 一鍵重置所有學生（清除所有志願、帳號、Session）

## 客製化你的單位資訊

如果要把這個專案 clone 給自己的學校/單位使用，只需要改 `public/site-config.js` 這一個檔案：

```js
const SITE_CONFIG = {
    siteName: '展覽位置預定系統',      // 系統名稱（頁籤標題、左上角站名）
    orgName: 'hui.gallery',           // 頁尾版權顯示的單位名稱
    contactEmail: 'service@hui.gallery', // 聯絡信箱
    domain: 'booking.hui.art',        // 網站網域（忘記密碼信件範本會用到）
};
```

`index.html`、`book.html`、`result.html`、`admin.html` 都會載入這個檔案並自動套用，不需要一頁一頁改。**例外是 `verify-lottery.html`**：這頁刻意做成完全獨立、不連任何外部資源的單一檔案（連 `/site-config.js` 都不引用），確保使用者存成本機檔案後仍能離線使用，所以這頁的 `siteName`/`orgName`/`contactEmail` 是直接寫死在自己的 `<script>` 裡（在檔案接近尾端，`SITE_CONFIG` 這個 const 旁邊有註解），客製化時要記得**這頁另外手動改一次**。

另外，`wrangler.toml` 裡的 Cloudflare Pages 專案名稱（`name = "hui-booking"`）跟 `database_id` 也要換成你自己的，見下方「部署」章節。

## 效能與防護

`result.html` 是公開頁面，會被大量、長時間開著自動輪詢，人數規模變大（或有人惡意狂打 API）時，如果每次請求都直接查資料庫，D1 的讀取量跟 Cloudflare 帳單都可能被撐爆。目前的因應設計：

- **前端輪詢**：每 30 秒自動更新一次（不是即時）；分頁切到背景（切走分頁、鎖螢幕）時會暫停，切回前景立即補刷新一次。
- **後端邊緣快取**（`/api/result`，使用 Cloudflare Workers 的 `caches.default`）：同一個專案在快取有效期間內，不管同時有多少人查看，資料庫只會真正被查詢一次。登入者（在意自己結果）快取 4 秒，未登入的一般訪客快取 20 秒；全體學生名單（跟專案無關）另外獨立快取 60 秒，不隨各專案回應重複查詢。**代表資料最多可能有數秒到數十秒的延遲，這是刻意的設計取捨，不是 bug。**
- **Cloudflare Rate Limiting Rule**（在 Cloudflare Dashboard 手動設定，不在程式碼裡）：網域層級對 `/api/*` 設定「同一 IP 每 10 秒最多 10 次請求，超過封鎖 10 秒」，防止異常高頻請求或惡意狂打 API。Free 方案的速率限制規則只有 1 條額度、動作只能選「封鎖」、封鎖時間只能跟統計期間相同，升級方案可以有更細緻的設定（例如先「記錄」觀察再封鎖）。
- **D1 用量預算警示**：Cloudflare Dashboard → D1 資料庫 → 用量 → 計費儀表板可以設定支出警示，多一道安全網。

如果要換 Cloudflare 帳號或重建網域，**Rate Limiting Rule 跟預算警示都要手動重新設定一次**，這兩項不會隨程式碼部署自動套用。

## 部署

> **不熟悉指令列？** 有一份完全用滑鼠點擊 Cloudflare / GitHub 網頁介面、不用安裝任何軟體的教學：[DEPLOY_GUI.md](DEPLOY_GUI.md)。下面是給熟悉指令列的開發者看的版本。

### 前置

```bash
npm install -g wrangler
wrangler login
```

### 建立 D1 資料庫

```bash
wrangler d1 create hui-booking-db
```

將輸出的 `database_id` 填入 `wrangler.toml`。

### 初始化資料表

**全新建立的資料庫**（例如換一個 Cloudflare 帳號、開發用資料庫、或正式站資料庫損毀需要重建）依序執行全部：

```bash
wrangler d1 execute hui-booking-db --remote --file=./schema.sql
wrangler d1 execute hui-booking-db --remote --file=./migrations/002_admin_roles.sql
wrangler d1 execute hui-booking-db --remote --file=./migrations/003_note.sql
wrangler d1 execute hui-booking-db --remote --file=./migrations/004_drive_url.sql
wrangler d1 execute hui-booking-db --remote --file=./migrations/005_no_password.sql
wrangler d1 execute hui-booking-db --remote --file=./migrations/006_backfill_missing_columns.sql
wrangler d1 execute hui-booking-db --remote --file=./migrations/007_max_combo_size.sql
wrangler d1 execute hui-booking-db --remote --file=./migrations/008_active_until.sql
wrangler d1 execute hui-booking-db --remote --file=./migrations/009_lottery.sql
wrangler d1 execute hui-booking-db --remote --file=./migrations/010_lottery_signature.sql
```

> **注意**：目前正式站的資料庫欄位大多已經齊全（`002`、`006` 涵蓋的欄位是先前直接在 Cloudflare
> D1 Console 手動加上的，沒有同步寫成 migration 檔）。**請勿**在正式站資料庫上重複執行 `002`
> 或 `006`，欄位已存在會直接報錯（`duplicate column name`）。這兩份檔案只在建立一個全新、空白

### 設定環境變數

```bash
wrangler pages secret put ADMIN_PASSWORD      # 管理員登入密碼
wrangler pages secret put SUPER_PASSWORD      # 超級管理員緊急密碼（選填）
wrangler pages secret put LOTTERY_SIGNING_KEY # 抽籤結果數位簽章私鑰（選填，見下方說明）
```

`LOTTERY_SIGNING_KEY` 是抽籤結果數位簽章用的 ECDSA P-256 私鑰，格式為 JWK 的 JSON 字串（一整行）。沒有設定時抽籤功能仍會正常運作，只是抽籤紀錄不會有簽章，`verify-lottery.html` 會顯示「無簽章可驗證」。**這把私鑰不會、也不該出現在任何 git 版本紀錄裡**，只透過 Cloudflare Dashboard 或 `wrangler pages secret put` 設定；對應的公鑰（本身不是秘密）已經寫死在 `public/verify-lottery.html` 裡。

### 部署

Push 到 GitHub 後，在 Cloudflare Dashboard 建立 Pages 專案：

- Framework preset：None
- Build command：（留空）
- Build output directory：`public`

建立後至 **Settings → Bindings** 新增 D1 binding，variable name 設為 `DB`，選擇 `hui-booking-db`，再觸發一次重新部署。

也可直接用 CLI 部署：

```bash
npx wrangler pages deploy public --project-name hui-booking
```
